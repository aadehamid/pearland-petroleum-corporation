## 1. Placement and security boundary

Under [ADR-0045](../../adr/0045-delta-lake-on-r2-and-databricks-portability.md), [ADR-0046](../../adr/0046-ot-it-integration-split-sparkplug-nats-outbox.md), [ADR-0047](../../adr/0047-slice1-active-core-vs-staged-apps.md), [ADR-0051](../../adr/0051-exe-dev-r2-databricks-hosting-and-recovery.md), and [ADR-0053](../../adr/0053-legacy-data-quarantine-and-world-export-bundle.md), PPC runs remotely without laptop dependency (`EA-CLOUD-001`) under a strict no-paid-commercial-license constraint (with Cloudflare R2 as the explicit free-tier exception, `T52`/`T79`):

- **Durable source-of-truth tier (Cloudflare R2):** raw public and source evidence, canonical world checkpoints (`evaluation/hidden/`), **Delta Lake** analytical tables written solely by `delta-rs` (`aws_conditional_put="etag"`, `ADR-0045`), immutable `ReleaseManifest` files, `WorldExportBundle` observable exports (`ADR-0053`), and quarantined `LEGACY_PRE_WORLD_MODEL` prefixes (`ADR-0053`). R2 is durable object storage, not an OLTP database; self-hosted MinIO on `exe.dev` remains a local offline option only (`T81`).
- **Operational runtime tier (`exe.dev` persistent VMs with local Docker Compose parity for dev/CI):** PostgreSQL (CTRM, TimescaleDB historian, pgvector evidence, Dagster metadata, atomic Silver staging/inbox), MySQL (Logistics), SQLite (Refinery/LIMS edge), NATS JetStream (IT events), Mosquitto (OT Sparkplug B), Neo4j Community (mounted `/data`, strictly a rebuildable projection with offline `neo4j-admin dump` to R2; no Neo4j Enterprise entitlement), Dagster webserver/daemon, FastAPI backend (Python-first per `T75`; FastAPI Cloud stays an optional managed swap per `T81`), Plotly Dash workspace (Slice 1), and OTel tracing (ClickHouse-backed Langfuse v3 requires 12–16 GB total stack RAM and a two-VM split or Slice 1 lightweight OTel collector; Cloudflare D1 retention vs Postgres workflow consolidation is resolved in WP-0; see [PPC-REVIEW-003 §2](../independent-review/PPC-REVIEW-003_System_and_Decision_Register.md#2-per-store-backup-recovery-and-exedev-sizing-matrix)).
- **Enterprise portability tier (Databricks Free Edition → paid Databricks):** per T86, Free Edition lacks custom R2 external storage locations and consumes a synced/ingested copy into workspace-managed Delta (`WP-8`), while paid Databricks uses Unity Catalog external locations (Approach A) or managed migration (Approach B) (`ADR-0045`, `ADR-0051`).
- **Recovery objectives (`ADR-0051`):** zero silent data loss across committed world checkpoints and all active source outboxes (per-store backup matrix in [PPC-REVIEW-003 §2](../independent-review/PPC-REVIEW-003_System_and_Decision_Register.md#2-per-store-backup-recovery-and-exedev-sizing-matrix): Postgres WAL, MySQL binlog, SQLite Litestream, Neo4j offline dump, NATS outbox re-derivation, D1 export if retained); full deterministic rebuild within 1 hour (`RTO <= 1 hour` for Slice 1 volume `<= 5 GB` compressed), proven by a WP-4 restore drill before Slice 1 release. No production or real OT access is authorized.

`ServiceDescriptor` records service ID, image/source digest, configuration digest, environment, branch scope, data authority, upstream release pins, secret references, network routes, health checks, backup policy, recovery objective and deployment status. `OperationRecord` has operation ID, service ID, environment, branch ID, actor, action, time, result and evidence locator. `BackupManifest` records backup ID, created-at time, `branch_id`, environment, consistent source cut, world checkpoint ID, outbox/inbox positions, table manifests, graph rebuild boundary, object hashes, database log position, encryption key reference and restore test. Secrets are never embedded in manifests or documents. Roles separate world truth, source apps, integration, evidence retrieval, hidden evaluation and approval execution. Each service may read only its assigned scope.

Deployment transitions are `DEFINED → DEPLOYED`, `DEPLOYED → HEALTHY|DEGRADED`, `HEALTHY → VERIFIED|DEGRADED`, `DEGRADED → RECOVERING`, `RECOVERING → HEALTHY|DEGRADED`, and `VERIFIED → DEGRADED`; a health endpoint alone does not mean a release is qualified. Recovery must establish source database and outbox/inbox positions, table manifests, world checkpoint and graph rebuild boundary before advertising readiness. Monitoring tracks lag, rejected mappings, replay errors, release state and access denial without logging restricted payloads.

## 2. Synthetic recovery fixture

In a `SYNTHETIC` quality-rejection run, a source ticket commits at 08:05 and its outbox message is pending. A worker fails at 08:06. Restore from a backup at 08:00 plus the source log, then drain the outbox. The expected result is one ticket and one applied downstream business effect. A published analytical release must remain at its prior watermark until reconciliation succeeds. A graph may rebuild from that release; it cannot create another physical receipt. A compromised retrieval role must fail to read canonical world or hidden-evaluation objects. A sibling branch restore cannot adopt baseline state without explicit branch provenance.

## 3. Qualification and options

Record restore duration (`RTO <= 1 hour`), data-loss bound (`RPO` = last committed R2 manifest and WAL), integrity hashes, source log positions, failed-secret and denied-route tests, backup corruption, replay, `exe.dev` VM memory/CPU sizing for Neo4j + Postgres + NATS, single-writer Delta-on-R2 commit verification, and cross-service cut consistency. Verify R2 retention and recovery with a WP-4 restore drill, not a storage setting alone. No deployment, restore or entitlement test is claimed (**planned**).
