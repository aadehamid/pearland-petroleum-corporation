## 1. Placement and security boundary

Under [ADR-0045](../../adr/0045-delta-lake-on-r2-and-databricks-portability.md), [ADR-0046](../../adr/0046-ot-it-integration-split-sparkplug-nats-outbox.md), [ADR-0047](../../adr/0047-slice1-active-core-vs-staged-apps.md), [ADR-0051](../../adr/0051-exe-dev-r2-databricks-hosting-and-recovery.md), and [ADR-0053](../../adr/0053-legacy-data-quarantine-and-world-export-bundle.md), PPC runs remotely without laptop dependency (`EA-CLOUD-001`) under a strict no-paid-commercial-license constraint (with Cloudflare R2 as the explicit free-tier exception, `T52`/`T79`):

- **Durable source-of-truth tier (Cloudflare R2):** raw public and source evidence, canonical world checkpoints (`evaluation/hidden/world_version=.../`), **Delta Lake** analytical tables written solely by `delta-rs` (`aws_conditional_put="etag"`, `ADR-0045`), immutable `ReleaseManifest` files, hourly OTLP JSON traces (`telemetry/otel/`, `ADR-0055`), `WorldExportBundle` observable exports (`ADR-0053`), and manifest-inventoried `LEGACY_PRE_WORLD_MODEL` records (`ADR-0053`). R2 is durable object storage, not an OLTP database; self-hosted MinIO on `exe.dev` remains a local offline option only (`T81`).
- **Operational runtime tier (`exe.dev` 12 GB VM with local Docker Compose parity for dev/CI, `ADR-0055`):** runs on **one 12 GB `exe.dev` VM** (or two VMs, `8 GB` stores plus `4 GB` apps, with identical Compose files if `exe.dev` cannot provision 12 GB on one VM; no local Ollama). Services: PostgreSQL (CTRM, TimescaleDB historian, pgvector evidence, Dagster metadata, atomic Silver staging/inbox, and **all workflow, approval, RBAC user/role, and LangGraph checkpoint state — no Cloudflare D1 in v1**), MySQL (Logistics), SQLite (Refinery/LIMS edge), NATS JetStream (IT events), Mosquitto (OT Sparkplug B), Neo4j Community (mounted `/data`, strictly a rebuildable projection with offline `neo4j-admin dump` to R2; no Neo4j Enterprise entitlement), Dagster webserver/daemon, FastAPI backend (enforcing signed JWT/session authentication against PostgreSQL `users`/`role_assignments`; Python-first per `T75`), MLflow tracking (`ADR-0048`), Plotly Dash workspace (Slice 1), and lightweight OpenTelemetry Collector shipping hourly OTLP JSON to R2 `telemetry/otel/` (ClickHouse-backed Langfuse v3 stages to `WP-7`; see [PPC-REVIEW-003 §2](../independent-review/PPC-REVIEW-003_System_and_Decision_Register.md#2-per-store-backup-recovery-and-exedev-sizing-matrix)).
- **Enterprise portability tier (Databricks Free Edition -> paid Databricks, `ADR-0055`):** per `T86`, Free Edition lacks custom R2 external storage locations; in `WP-8A`, a Dagster job on `exe.dev` (never a laptop) copies pinned Delta tables into Databricks Free Edition workspace-managed tables using the mechanism validated in the `WP-0` ingest probe (stopping to raise an ADR if none works), while paid Databricks Unity Catalog external locations remain documented only (`ADR-0045`, `ADR-0051`, `ADR-0055`).
- **Recovery objectives (`ADR-0051`, `ADR-0055`):** zero silent data loss across committed world checkpoints and all active source outboxes (per-store backup matrix in [PPC-REVIEW-003 §2](../independent-review/PPC-REVIEW-003_System_and_Decision_Register.md#2-per-store-backup-recovery-and-exedev-sizing-matrix): Postgres WAL, MySQL binlog, SQLite Litestream on a `60-second` sync cadence with R2 free-tier write-operation budget verified in `WP-4A`, Neo4j offline dump, NATS outbox re-derivation; every WAL/binlog restore compares each source outbox's highest committed sequence number against PostgreSQL `InboxReceipt` high-water marks and R2 raw logs, flagging any gap within the `<= 5 min` window as `RECOVERY_GAP`); full deterministic rebuild within 1 hour (`RTO <= 1 hour` for Slice 1 volume `<= 5 GB` compressed), provisioned with a stub-writer baseline drill in `WP-4A` and proven against live outbox and Delta writers in `WP-4B` (`R4` gate before `WP-5`). No production or real OT access is authorized.

`ServiceDescriptor` records service ID, image/source digest, configuration digest, environment, branch scope, data authority, upstream release pins, secret references, network routes, health checks, backup policy, recovery objective and deployment status. `OperationRecord` has operation ID, service ID, environment, branch ID, actor, action, time, result and evidence locator. `BackupManifest` records backup ID, created-at time, `branch_id`, environment, consistent source cut, world checkpoint ID, outbox/inbox positions, table manifests, graph rebuild boundary, object hashes, database log position, encryption key reference and restore test. Secrets are never embedded in manifests or documents. Roles separate world truth, source apps, integration, evidence retrieval, hidden evaluation and approval execution. Each service may read only its assigned scope.

Deployment transitions are `DEFINED → DEPLOYED`, `DEPLOYED → HEALTHY|DEGRADED`, `HEALTHY → VERIFIED|DEGRADED`, `DEGRADED → RECOVERING`, `RECOVERING → HEALTHY|DEGRADED`, and `VERIFIED → DEGRADED`; a health endpoint alone does not mean a release is qualified. Recovery must establish source database and outbox/inbox positions, table manifests, world checkpoint and graph rebuild boundary before advertising readiness. Monitoring tracks lag, rejected mappings, replay errors, release state and access denial without logging restricted payloads.

## 2. Synthetic recovery fixture

In a `SYNTHETIC` quality-rejection run, a source ticket commits at 08:05 and its outbox message is pending. A worker fails at 08:06. Restore from a backup at 08:00 plus the source log, then drain the outbox. The expected result is one ticket and one applied downstream business effect. A published analytical release must remain at its prior watermark until reconciliation succeeds. A graph may rebuild from that release; it cannot create another physical receipt. A compromised retrieval role must fail to read canonical world or hidden-evaluation objects. A sibling branch restore cannot adopt baseline state without explicit branch provenance.

## 3. Qualification and options

Record restore duration (`RTO <= 1 hour`), data-loss bound (`RPO` = last committed R2 manifest and WAL), integrity hashes, source log positions, failed-secret and denied-route tests, backup corruption, replay, `exe.dev` VM memory/CPU sizing for Neo4j + Postgres + NATS, single-writer Delta-on-R2 commit verification, and cross-service cut consistency. Verify R2 retention and recovery with the live `WP-4B` restore drill (after `WP-4A` provisioning/stub-writer baseline and `WP-3` live outbox and Delta writers), not a storage setting or stub drill alone. No deployment, restore or entitlement test is claimed (**planned**).
