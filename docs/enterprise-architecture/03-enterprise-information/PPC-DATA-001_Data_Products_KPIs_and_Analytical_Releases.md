## 1. Product and calculation boundary

Domain owners publish products at a stated business grain. Raw preserves source bytes and native keys. Silver reconciles identity, units and time without hiding disagreement. Gold contains reusable domain facts. A KPI value uses an approved EPM definition and governed computation, preserving EPM's tall KPI fact and governed dimension-link structure (T100, `EA04B-D08`). Every quantitative series declares its **Measure Class** ([GLOSSARY.md](../../../GLOSSARY.md), T100) — `KPI`, `OPERATIONAL_METRIC`, or `MARKET_INDICATOR` — and every KPI exposes explicit decomposition into its constituent operational metrics and market indicators. A semantic URI supplies meaning, not arithmetic. Superset, Dash, Relate, APIs, and agents read approved consumption views. [PPC-013](../../PPC-013_Cloudflare_R2_Durability_and_Project_Storage_Standard.md) governs durable objects. Under [ADR-0045](../../adr/0045-delta-lake-on-r2-and-databricks-portability.md) (confirming T86), **Delta Lake on Cloudflare R2** replaces DuckLake as PPC's analytical table format. **`delta-rs` (`deltalake`) with `aws_conditional_put="etag"`** and a Dagster concurrency pool of `1` per table is the sole Delta writer (using idempotent `txnAppId`/`txnVersion` metadata); **DuckDB is strictly read-only** against Delta tables. Per T86 and [ADR-0055](../../adr/0055-slice1-hosting-observability-postgres-workflow-and-databricks-sync.md), Databricks Free Edition does not support custom R2 external storage locations and therefore reads a Dagster-synced copy into workspace-managed Delta (`WP-8A`), while paid Databricks Unity Catalog external locations remain documented only (`ADR-018` clarified, `EA06A-D06`).

## 2. Typed contracts and lifecycle

`ProductContract`: `product_id`, owner, version, row grain, primary dimensions, branch policy, event and source times, provenance class, schema digest, source dependencies, access label, freshness bound, null policy and quality tests. `MeasureContract`: quantity ID, approved meaning/version, unit and basis, formula pointer, aggregation rule, missing-value policy and tolerance. `KPIContract`: approved EPM ID/version, owner, supplying product ID, objective, measure IDs, approved formula pointer, unit and basis, period/grain, target and threshold version. Formula authority remains the released EPM contract. `ValueRecord`: immutable value ID, `measure_id` and `kpi_id` where applicable, definition and threshold versions, branch, period, dimensions, numeric value or explicit unknown with `unknown_reason`, unit and unit basis or currency, calculation digest, input release, `provenance_class`, separate `threshold_status` and `quality_status`, and restatement-of ID, publication ID, subject scope, scoped ordinal, supersedes-publication ID, source-recorded time, published-at time, authorization label and recipient/role-and-channel availability relation from [INFO-001 §3](PPC-INFO-001_Enterprise_Ontology_Identity_and_Time.md). Every material input and output value carries `OBSERVED`, `DERIVED`, `ESTIMATED`, `SYNTHETIC` or `SCENARIO_ASSUMPTION`.

`ReleaseManifest`: release ID, publication ID, subject scope, scoped ordinal, supersedes-release ID, source-recorded time, authorization label, `PREPARING|VALIDATED|PUBLISHED|RETRACTED|REJECTED`, published-at time, recipient/role-and-channel availability relation, EPM release ID, world version, table snapshot IDs, per-source captured/durable/applied/published watermarks, `branch_id`, semantic and mapping digests, model version, reconciliation report, access scope and approval evidence. `PUBLISHED` is atomic at the manifest boundary. The release transitions `PREPARING → VALIDATED|REJECTED`, `VALIDATED → PUBLISHED|REJECTED`, and `PUBLISHED → RETRACTED`. `REJECTED` and `RETRACTED` are terminal; a corrected release gets a new ID. A retraction is a separate immutable event with release ID, `retracted_at`, source-recorded time, published time, recipient/role-and-channel receipt and authorization label. A reader at cutoff C treats retraction as effective only if the retraction event was published, delivered and authorized by C. An earlier cutoff retains the published release. Later cutoffs select the highest eligible unretracted release in that scope, or return `UNRESOLVED`. A retraction does not edit the release or erase historical receipts. An incomplete watermark blocks validation and records the reason in the rejected candidate. Publication is recipient-specific for reads under [INFO-001 §3](PPC-INFO-001_Enterprise_Ontology_Identity_and_Time.md). A table snapshot alone is not a business-consistent release. Late source data creates a later release and, when needed, a restated value. Historical values remain addressable.

For a separate `SYNTHETIC` release fixture, planner has a historical grant for workspace, purpose `tank-review` and label OPERATIONS from 09:00 onward. The grant was recorded at 09:00. The release and retraction share branch baseline and scope tank S.

| Event ID / kind | Release ID | Recorded at | Effective at | Published at | Planner workspace receipt | Label |
|---|---|---|---|---|---|---|
| L1 / PUBLISHED | L1 | 10:00 | 10:00 | 10:00 | 10:05 | OPERATIONS |
| X1 / RETRACTED | L1 | 11:00 | 11:00 | 11:10 | 11:15 | OPERATIONS |

A 10:30 or 11:14 cutoff still selects L1. At 11:15, X1 makes L1 ineligible and the reader returns `UNRESOLVED` unless an earlier eligible release exists. A second reader without X1 delivery still sees L1. This fixture checks the as-of rule only; it does not qualify a release implementation.

## 3. Worked quantity and adverse cases

The following is separate `SYNTHETIC` integration retry fixture `INT-RETRY-01`, not the T125 tank oracle or a certified KPI. All volumes use one liquid at constant density on a common reference-volume basis. A tank starts at 1,000 bbl. A received 200 bbl and dispatched 150 bbl give a `DERIVED` closing balance of 1,050 bbl (`1,000 + 200 − 150`). A product cannot publish if dispatch is still captured but not applied: its release must report an incomplete watermark, not 1,200 bbl as final. A repeated 200 bbl receipt with the same source movement ID contributes zero additional barrels. A corrected dispatch of 160 bbl gives a new `DERIVED` balance of 1,040 bbl in a restatement; the earlier release stays reproducible.

For separate `SYNTHETIC` utilization illustration `UTIL-ILLUS-01` only, 80,000 bbl/day divided by 100,000 bbl/day is 0.8, or 80% (`DERIVED`). Both values must share unit basis, day length and branch. This number is not an official KPI until a released EPM definition, scope, numerator/denominator policy, threshold and approved product are pinned. A 23-hour local day cannot silently be treated as 24 elapsed hours. A model forecast is `ESTIMATED`; a hypothetical outage is `SCENARIO_ASSUMPTION`, even when both are displayed beside source facts.

## 4. Qualification and unresolved choices

Qualify grain uniqueness, units, null behavior, source-to-Gold reconciliation, formula parity with an independent reference, threshold status, role filtering, incomplete-release rejection, replay, restatement and cross-engine equivalence. Record row-level expected and observed values, manifests, code and EPM digests, tolerances and approval. No such execution is claimed here.
